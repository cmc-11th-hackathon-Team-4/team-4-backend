# 0001. 서버 접속·배포는 SSH(pem) 대신 SSM

- 상태: 채택
- 날짜: 2026-11-21 (PR #1 에서 도입, 같은 날 팀에서 유지하기로 재확인)

## 배경

EC2 에 사람이 접속하고 GitHub Actions 가 배포해야 한다. 흔한 방법은 pem 키 + SSH 다.

## 결정

pem 키를 쓰지 않는다. 사람은 Session Manager, Actions 는 `ssm send-command` 로 서버의 배포 스크립트만 실행한다.

## 결과

- 키 파일을 팀원끼리 나눠 가질 필요가 없다. 권한은 각자의 AWS 계정(IAM)으로 주고 회수한다.
- GitHub Secrets 에 서버 전체 권한(pem)이 아니라 "S3 업로드 + 특정 인스턴스에 명령 1종" 권한만 있다.
- 누가 언제 무엇을 실행했는지 AWS 에 기록이 남는다.
- 단점: `ssh -i` 한 줄 접속, `scp` 가 안 된다. 파일은 S3 를 거친다.
- 보안 그룹 22 번은 배포에 필요 없어 2026-11-22 에 닫았다 (그 전까지는 `0.0.0.0/0` 으로 열려 있었다).
